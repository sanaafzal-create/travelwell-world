## Locked principles
- **Payments: never touch the card; the provider is always merchant of record.** Atlas may **close the booking on our own surface** (orchestrate discover → decide → book — no leaky handoff), *but* the **provider/aggregator stays merchant of record and holds the card** (Duffel Payments, aggregator billing, or Stripe's hosted checkout where the card goes to Stripe, never our servers). So TravelWell **never touches card data** (stays PCI SAQ A) and **never becomes the seller of record** — which keeps chargebacks, refunds, fraud, and US seller-of-travel bonding off us. There is no tier where Atlas holds the card.
  - **Two things stay separate, on purpose (David-locked) — so merchant-of-record never sneaks in the back door:** **customer ownership** is *always ours* — Atlas closes on our surface and owns the relationship + the data; the traveler never gets handed off. **Merchant of record** is *always the provider's* — who legally sells, holds the card, and eats refunds/chargebacks/fraud/bonding. **We get full customer ownership from the first without ever taking the second.** "Own the customer" does **not** imply "be the merchant" — never conflate them.
  - **Becoming merchant of record (taking the payment ourselves) is a separate, deliberate, funded decision** (PCI-DSS scope + bonding + liability) — never a drift. It's **staged (David-locked): Stage 1 = provider-as-MoR now; Stage 2 = a deliberate post-funding flip** to unlock the big-player lanes (Ultra Virtuoso + IATA — the TravelWell-Ultra dominance play), gated ~$2M gross travel sales (Virtuoso threshold), walked in bonded and on purpose. Stage the treasury rail (Airwallex/Stripe, our-money-only) now; build swappable toward the flip. Plain-language today: *"you're paying [the provider] directly, right here,"* never *"I'll hold it for you."*
  - **NEVER assume one payer per itinerary (David-locked 2026-08-17).** Split payment across a group is a **year-three** feature — collecting from six cards makes us merchant of record *definitionally*, so it sits behind the same accreditation gate as everything else in that set. Nothing to build now, and exactly one thing not to do: **no single-payer assumption anywhere in the itinerary or booking model.** It costs nothing to honour today, because the itinerary already separates *placed* from *booked* with intermediate states — so **a share is a state on a placed experience, not a payment record.** The socket exists; it only has to stay open. If a single-payer assumption ever looks like the simpler build, **flag it rather than take it** — discovering it later is the expensive version. The design, when it comes, is a **small deposit plus a stated deadline** ("six people by Friday or the holds release") and not re-authorisation: a group booking takes weeks to fill, a hold does not survive that, and every refresh can fail on a replaced card. A deposit is a completed payment with no expiry to manage, and it self-selects for people who actually travel. It also earns a demo line — group travel is what every platform handles badly, and naming the constraint accurately beats claiming it works. Same argument as the safety spine.
- **Safer-Informed:** we keep travelers **informed** so they can be as safe as possible — we **never promise "safe"** (an outcome we don't control). L1/L2 book freely; L3 books only if it passes all three safety gates; L4 and L3-blocked are content-only (no Book button).
- **Never commit secrets.** The repo is public. `ANTHROPIC_API_KEY` and `UNSPLASH_ACCESS_KEY` live as **Supabase secrets** — never `VITE_`, never in the repo. Never put a model identifier in commits, PRs, or code.
- **Voice = adapter seam, never welded (David).** The vendor landscape (STT/TTS/turn-detection/frameworks) shifts month to month, so any voice capability goes **behind our own thin interface** — the app calls `speak()`/listen, never a vendor directly (today: browser Web Speech in `src/lib/useSpeech.ts` + `src/lib/voice.ts`; tomorrow: LiveKit belt + Deepgram ears + a **Cartesia _or_ ElevenLabs** mouth drop in behind the same seam — both live as sibling `Mouth` adapters (`src/lib/voice/`), so the pick is a one-line/env flip (`VITE_TWW_MOUTH`), decided by ear on real lines: Cartesia for latency, ElevenLabs for fidelity). **The real-time voice pipeline is spike-PROVEN (David, 2026-08): Atlas hears + talks back live, brain still ours.** **Never build Atlas's logic inside a vendor's all-in-one agent format** (OpenAI Realtime, ElevenLabs Conversational, Deepgram Voice Agent) — that welds us. The **brain stays ours** (Claude in our own edge function). The on-screen text is always the guaranteed fallback (ties to Accessibility). Voice answers are terse (the "voice mode" brevity rules) — voice needs ~60–70% shorter replies than text. **Voice Atlas carries the SAME canon as typed Atlas** (`voice-agent/index.ts` vs `supabase/functions/atlas/index.ts`) — only the length differs; its catalog block is **generated from `taxonomy.ts` at start-up**, so never hand-type the roster into a prompt. **The worker is not deployed anywhere** — it runs wherever someone starts it, so live voice depends on that process being up.

## Safety controls — placement is ours, one rule is David's (2026-08-10)
David handed over placement and hierarchy of the safety set, keeping one requirement: **EMERGENCY stays prominent and unmistakable — the thing a person finds in a hurry, on a phone, without hunting.** He added the constraint that matters most: **an emergency call needs no data and no SIM (112 connects on any available network), so the button has to be findable in exactly the moment nothing else on the page will load.**
- **One emergency control, in the sticky header** — solid red, white cross, labelled "Emergency" (label collapses on a narrow header; the red pill and cross never do). Present on every page at every scroll position, and it **cannot overlap content**, which the old floating stack did at every width.
- **The floating safety stack is gone.** Human/Pet care finders are locators, not crisis controls; they live on a **Nearby** tab inside the safety panel.
- **The advisory cascade is country → destination.** `resolveSafety(dest, iso)` in `safety-data.ts` is the only correct read: the country record is the baseline, a dossier's `data.safety.advisory_level` overrides it for a named zone, and a differing carve-out is LABELLED with the country level so the card never contradicts the government page without saying why. `booking_hold` (implied by L4) prints the content-only line. Never call `getSafety()` straight from a destination page.
- **A named area with a level attached is STRUCTURED, never prose.** Sub-country carve-outs live in `zones[]` on the country row in `safety.json` (`{name, lvl, except?, note?}`), and a destination dossier joins by exact name via `data.safety.zone` — never by its own name or `sub_region`, because fuzzy geography is how a place silently inherits the wrong advisory. **Ten of thirty-six country rows carried their Level 3/4 zones as a sentence inside `considerations`** (2026-08-17): it rendered correctly and no code could see it, because the booking gate reads `lvl`, which is the *country* number — a destination inside a Do-Not-Travel zone would have shown Level 2 and offered a Book button. Nothing was live-wrong only because all 44 live destinations sit in the mainstream part of their country: **luck, not a gate.** `except` is load-bearing in both directions — dropping State's "except Davao City, Davao del Norte, Siargao Island and the Dinagat Islands" holds four bookable places at Level 3, and an over-restriction is still an inaccuracy. **The level lives on the country row once**, so when a source moves a zone, one row changes and every destination in it follows. A `zone` + `advisory_level` that disagree resolve to the **stricter**; an unresolvable zone name is a hard error at `validate:ingest` and fails safe at runtime (no level printed, booking held). `gen:ground-truth` fails if a level claim goes back into prose. Shape + worked example: `docs/ingest-contract.md` §3b.
- **Traveler-facing advisory links are DEEP links** to that country's page on State / FCDO / CDC (`src/data/advisory-sources.ts`), never a homepage. No confirmed slug → the source's index, and the page says so; a 404 reads as "we checked" when we didn't. **`npm run check:advisory-links` proves them** — needs outbound network, so run it where there is some before they go public. **A blocked run is not a passing run:** it exits 2 when nothing was reached and 3 when only some were, because "no 404s" is trivially true when zero links were fetched — a verifier that can hand back a tick without verifying is worse than none, since it's the thing someone points at before shipping.
- **Global advisories are separate from country levels.** A State Worldwide Caution applies everywhere and changes no country's number, so it renders as its own note above the card (`advisory-global.ts` + `GlobalAdvisoryNote`), quoted VERBATIM and attributed to its issuer — a US caution to US citizens is that, not a TravelWell verdict. `active: false` retires it everywhere in one edit; a stale worldwide banner trains people to ignore banners.
- **The FCDO is the PRIMARY advisory source (David 2026-08-13); State is enrichment** while State is unreadable from our servers. **The State API needs BOTH a browser User-Agent and a non-datacenter IP** — the 2×2 in `docs/advisory-checker.md` has one working cell (laptop + browser UA → 952KB); a datacenter IP returns `[]` even with a full Chrome UA, so **no header tuning in the Edge Function will fix it** and that line of work is closed. Getting State read automatically needs a registered key or a non-datacenter egress. **This was diagnosed wrong three times in two days, each time from a single measurement** — twice by asserting a cause and once by "refuting" it with a command that changed two variables at once. **Add a cell to the matrix; never re-diagnose it from one data point.** A measurement whose provenance isn't recorded is not evidence, and neither is one that moves two variables. **Primary ≠ supplies levels:** the FCDO publishes no numeric level, so our L1–L4 remain the curated `safety.json` baseline, and while State is unreachable the checker detects *change* but not a *level move* from the source that numbers them. Say that plainly; never soften it. A source we can't read is recorded as `degraded` (named, in `notes.degraded` and the response) — never as N per-country failures, which makes a healthy run look catastrophic and trains everyone to ignore the number.
- **The advisory sources are machine-readable — do not scrape pages** (David 2026-08-10): State's Consular Affairs API `cadataapi.state.gov/api/TravelAdvisories`, the RSS at `travel.state.gov/_res/rss/TAs.xml`, `cadatacatalog.state.gov`, and the FCDO via the GOV.UK Content API. Both still bot-block a bare fetch, so browser-like headers from an edge function are still needed — but applied to a structured endpoint, not a page that can be redesigned out from under us.
- **Atlas warns and then SOLVES (David-locked 2026-08-10).** At L3/L4 it surfaces the level and points at the guide instead of carrying on planning — but it must never read as a refusal. Never "you can't go there": always *"that area carries a Level 3 for this reason, here is where the risk sits versus where you'd be, and here are three places that give you the same thing at Level 1."* **The alternatives come in the same breath as the warning.** Every other travel site warns and stops; that contrast is the point.
- **The advisory checker is ONE job, run DAILY** (`supabase/functions/advisory-check` + migrations 0013/0014). **Any level move surfaces the SAME DAY, in either direction** (David 2026-08-11 — a de-escalation is not housekeeping: Uganda L4→L3 turns four gorilla destinations from never-bookable into bookable). The severity label survives but no longer gates timing; `text`-only changes are same-day for the FCDO (which publishes no numeric level, so its regional carve-outs move there and nowhere else) and routine for State. **the 1st and 15th are what we PUBLISH, not what we check** — a fortnightly sweep with a separate urgent path doubles the failure surface. **Freeze on failure**: `advisory_state` is written only on a successful read, so a source we couldn't reach keeps its previous value AND its previous `fetched_at` (stale stays visible). **Nothing auto-publishes** — a change lands in `advisory_changes` as `pending` for a human. Every run is logged, including quiet ones. The country list is an INPUT (`npm run gen:advisory-payload`) so a country can't silently go unchecked; regenerate it when a destination adds a country. Runbook: `docs/advisory-checker.md`.
- **The panel must stay network-free**: 112 always rendered, local numbers from the browser timezone (never a lookup), first aid as static content, every number a real `tel:` link. **Verified offline** (service worker + `setOffline`) — regression-test it that way, not just online.

## Accessibility — build to WCAG AA (locked design standard)
Stylish **and** usable by everyone. The elderly and low-vision traveler are among our best-spending markets — building genuinely *for* them is a **moat** (David), not a compliance chore — and "Atlas walks beside everyone" has to be true in the pixels, so accessibility is baked in from the first screen, never bolted on later (retrofitting a hardened UI is expensive). This is standing canon, right alongside the payments-never rule and the voice rule. Hold a real, checkable AA bar:
- **Contrast** meets AA (≥ 4.5:1 body, ≥ 3:1 large text) — audit muted grays on tinted grounds; no classy-but-unreadable light-gray-on-white.
- **Text resizes** without breaking (rem units; nothing that clips on zoom); a sensible default size.
- **Tap targets** big enough for a real thumb (~44px).
- **Every control labeled** for screen readers; **visible keyboard focus**; **never color alone** for meaning; respect `prefers-reduced-motion`.
- **Checkable, not a vibe** — automated a11y checks in the build so a regression fails the build, same discipline as the dossier QC gate.

## Placement & booking canon (locked — build-toward)
Shapes the experience / itinerary / provider records from the first pour so Atlas is a companion, not a catalog. Detail in `docs/status-and-launch-plan.md`.
- **Experiences carry structured fit-rules** — `duration / before / after / pairs_with / pace / time-of-day / season` as a fixed tag vocabulary, **inherited by experience type** (author "no-fly-after-diving" once for diving). Atlas *derives* the connective buffers (arrival rest, no-fly window, recovery morning) from these and **recomputes them on any reshuffle** — the safety spine is enforced, never stranded.
- **Itinerary is a first-class dated object** — ordered placed-experiences across dated days (day-number + weekday + date, always paired). **Placed ≠ booked** (idea → placed → handed-off → confirmed). One traveler owns many trips.

Confirmation-return is an **upgradeable field** (`email-parse` everywhere to start → `api` as each provider ships it). Provider is always merchant of record; Atlas never touches payment.

## The catalog → DB pipeline (important)
- The catalog is **authored in `src/data/`** (`places.ts`, `taxonomy.ts`, `*.json`) and in provider CSVs under `src/data/providers/`.
- `scripts/gen-catalog-seed.ts` (run via esbuild) **generates** the seed SQL migrations (`0003`–`0007`). **Do not hand-edit those generated files** — change the source in `src/data/` and regenerate.
  - Regenerate: `./node_modules/.bin/esbuild scripts/gen-catalog-seed.ts --bundle --platform=node --format=esm --outfile=scratchpad/gen.mjs && node scratchpad/gen.mjs`
- The app reads the catalog **DB-first with a bundle fallback** (`src/store/useCatalog.ts` + `src/lib/catalog.ts`). Production reads Supabase; the bundle covers offline/preview.
- After changing the catalog: regenerate the seed **and** re-run the affected migration in the Supabase SQL editor. Seeds are idempotent (`on conflict do update`); some self-heal schema (add columns, swap constraints) so a single re-run reconciles.
- **Drop-in dossiers — two folders, two gates.** Destinations: `src/data/destinations/*.json` → `npm run validate:ingest`. Special Interests: `src/data/interests/*.json` → `npm run validate:si`. `_`-prefixed files are references and never ship. Destination batches **replace** on id collision; SI batches **shallow-merge** (a data-only `{id, data}` patch is valid and must not blank the row).
- **The SI dossier is nine layers (David-locked 2026-08)** — `market · streams · sources · timing+events · map · providers · faq · wells/whispers/safety · seo/schema` in `special_interests.data` (migration 0012), typed as `SiData` in `taxonomy.ts`. **Every figure is `{label, value, confidence, source?}` and `confidence` is REQUIRED** (`verified` | `estimate`); `verified` without a `source` is a hard error. An unlabeled number is a guessed number — the gate refuses it. Contract: `docs/ingest-contract.md` §4; gold reference `src/data/interests/_REFERENCE.golf.json`.

## Working rules
- **`npm run gen:ground-truth` → `docs/ground-truth.md`** is the fact sheet for anyone (or anything) reasoning about this repo *without being able to read it*: every count, field path and vocabulary read from source with file:line, plus conformance checks that ask whether the data actually obeys the rules. **Regenerate and paste it rather than answering a field-name or count question from memory** — a confident recollection is indistinguishable from a lookup, which is exactly how a spec ends up built on a field that doesn't exist (Aug 2026: "booking windows are in §6 of the nineteen sections" — the dossier is nine layers, booking windows are 4a, and no SI carries a dossier at all). It's generated so it can't drift; a stale fact sheet launders a stale claim as a verified one.
- **A pre-commit hook runs every generator and refuses the commit if any generated file is out of step** (`.githooks/pre-commit` → `npm run check:generated`, ~1s). `npm install` enables it (`prepare` sets `core.hooksPath`); by hand it's `git config core.hooksPath .githooks`. It catches both shapes: a source edit that was never regenerated, and a hand-edit to a "do not hand-edit" file (regeneration silently repairs that one, so it's caught by a content hash taken before and after, not by asking git afterwards). Two real misses in two days prompted it — the slogan family stuck at 9 live interests after `wine` dropped, and the advisory link list still serving a Bahamas URL we'd already found dead. Nothing points at generated files from the code, so nobody remembers which edit touches which. **Generators must be idempotent** — `writeGenerated()` (`scripts/lib/write-generated.ts`) keeps a date stamp stable when only the date would change, because a check that fails every midnight is a check people pass with `--no-verify`.
- Run **`npm run build`** and **`npx tsc --noEmit`** green before committing.
- Develop on a feature branch; merge to `main` (fast-forward). Vercel deploys from `main`.
- **`www.travelwell.world` is the primary host (Sana-decided 2026-08-17); the apex 308s to it.** Every absolute URL we emit — canonicals, `og:url`, the sitemap, robots.txt's `Sitemap:` line, the Organization `@id` — comes from the single `ORIGIN` in `src/lib/site.ts`. Never hard-code the origin anywhere else: it lived in three copies and that is how a host ends up right in the sitemap and wrong in the canonical with nothing to catch it. All 121 sitemap URLs named the redirecting apex until this was fixed, which Search Console reports as 121 "Page with redirect" rows. Metadata must never disagree with what the server does.
- **Unknown paths must 404, not 200.** `vercel.json`'s rewrite list is **generated from the router** (`npm run gen:routes`, guarded by `check:generated`) — the old `/(.*)` → `/index.html` catch-all returned 200 with the home shell for every dead URL, so a previous build's pages stayed indexed indefinitely and could not age out. The generated list must equal the route table: a stale list 404s a *real* page, which is worse than the bug it fixed. `dist/404.html` carries `noindex, follow` and no canonical.
- Use the scratchpad dir for throwaway scripts; don't leave probes or unused deps in the repo.
- Planning/roadmap lives in `docs/status-and-launch-plan.md`; the sub_region canon in `docs/sub-region-master.md`.
